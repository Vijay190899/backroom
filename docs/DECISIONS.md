# Decision Log

Short ADRs. Newest at the bottom. Format: **Decision**, then *why*, then *alternatives*.

1. **Mock portals instead of real sites.** *Why:* reproducible benchmarks, no credentials, legal, can't break during the interview, and the chaos engine is only possible on sites we control. *Alt:* real sandbox sites (flaky, ToS issues).
2. **No bot-protection evasion.** *Why:* ToS and ethics; not a durable strategy. Human handoff is better UX. *Alt:* stealth browsers (rejected).
3. **Own browser-agent loop on Playwright + ARIA snapshots.** *Why:* skill compilation and healing are the differentiator and need full control and metrics. *Alt:* browser-use, Stagehand.
4. **Temporal graph in Postgres (custom) instead of Graphiti/Neo4j.** *Why:* one datastore, bitemporal SQL is simple, deterministic writers for structured data (no per-row LLM extraction cost), fewer moving parts to break. *Alt:* Graphiti + FalkorDB (richer, but LLM-heavy ingest and another service).
5. **"Agents for judgment, code for math."** *Why:* trust. LLMs never originate numbers, and the number guard enforces it. *Alt:* LLM-computed insights (hallucination risk).
6. **Cheap-by-default model ladder (Haiku 5.5 worker, Sonnet 5.5 planner), env-swappable.** *Why:* demo cost and latency; also a cost-aware multi-model talking point. *Alt:* Opus 5.5 everywhere (≈2× Sonnet; benchmark it in B4). *Amended by ADR-9:* the provider is swappable too.
7. **Vercel (web) + AWS Lightsail (backend, docker compose) + Caddy/sslip.io.** *Why:* their stack (Vercel + AWS), ~$12/mo, one box, two-minute rollback via snapshot. *Alt:* App Runner/ECS (more setup), Fly/Hetzner (not their stack).
8. **A single task runner: root `package.json` scripts (pnpm) on top of a uv workspace.** *Why:* one set of commands (`pnpm check | seed | bench | dev | e2e | probe:llm`) that works on Windows and Linux, in CI and on the server; `make` isn't available on Windows by default. *Alt:* Makefile, `just` (not installed), per-service READMEs (drift).
9. **LLM provider = OpenRouter by default, Anthropic direct as a switch (`LLM_PROVIDER`).** *Why:* the user's choice. One key, model flexibility for B4, same per-token Claude prices (verified 11 Nov). We keep a single code path: the official `anthropic` SDK against OpenRouter's Anthropic-compatible endpoint. *Trade-offs:* ~5.5% credit fee; Anthropic beta features (server-side fallbacks etc.) are off on OpenRouter and handled by the client escalation ladder; other features are confirmed by `pnpm probe:llm`, with results recorded here. *Alt:* the OpenAI-compatible OpenRouter API (second code path, loses Anthropic-native features); Anthropic direct only.
10. **Postgres is reached through a synchronous psycopg pool, called from worker threads.** *Why:* on Windows, psycopg's async mode needs the selector event loop while Playwright needs the proactor loop; one process can't have both. A sync pool behind `run_in_threadpool` works on Windows and Linux alike. *Alt:* async psycopg (breaks local dev on Windows), a separate browser process (more moving parts).
11. **The LLM spend ledger is an append-only JSONL file (`var/llm_ledger.jsonl`, `LLM_LEDGER_PATH`).** *Why:* the budget guard and the capability probe must work before the database exists, and one API process is the only writer. Per-run costs for the UI are stored with the run in Postgres (M2). *Alt:* a Postgres table (couples the probe to the DB).
12. **Theme switching is a 20-line inline script plus a `useSyncExternalStore` toggle, not `next-themes`.** *Why:* no flash of the wrong theme, no client-side script warning under React 19, one less dependency. *Alt:* `next-themes`.
13. **shadcn/ui is installed in its current default style (`base-nova`, Base UI primitives), with its colour variables mapped onto our `--t-*` tokens.** *Why:* the tokens in `apps/web/src/styles/tokens.css` stay the single source of colour; they are prefixed because shadcn already owns `--accent` and `--muted`. The primary button is ink, not caramel: white on caramel is only 3.1:1.
14. **Deploy images are built in GitHub Actions and pulled by the server (GHCR); nobody builds them locally.** *Why:* the api image is 4.3 GB (Playwright + Chromium), which a 2 GB Lightsail box and a light laptop cannot build comfortably, and a CI build is reproducible. *Alt:* build on the server (risk of running out of memory on deploy night).
15. **Two-machine workflow: light tasks on a laptop without Docker, heavy tasks on the main PC.** *Why:* the laptop is too light for Docker and Chromium, but most remaining work is plain code. Split by weight, contract-first (L0), with directory ownership and separate sync logs to avoid merge conflicts (HANDOVER §9). The laptop uses a free hosted Neon Postgres where it needs a database, and `pnpm dev:lite` otherwise. *Alt:* everything on the PC (serial; not enough time before the interview).
